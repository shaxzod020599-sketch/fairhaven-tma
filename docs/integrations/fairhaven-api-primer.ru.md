# Пример интеграции с API FairHaven Health

Пошаговое руководство: как подключиться к API нашей аптеки, читать каталог и
остатки, отправлять и обновлять заказы. Все примеры на Python (requests), но
логика одинакова для любого языка — это обычный HTTP.

Готовый рабочий модуль со всеми методами — в файле `fairhaven_client.py`.
Запустите `python fairhaven_client.py`, чтобы увидеть полный цикл вживую.

---

## Что понадобится

| Что | Значение |
|---|---|
| Базовый адрес | `https://api.fairhaven.uz/medicalka/v1` |
| Токен (чтение) | выдаётся при подключении, параметр `?token=` |
| Секрет (заказы) | выдаётся при подключении, параметр `?secret=` |

Две пары ключей на две задачи: токен — только для чтения каталога и остатков
(GET), секрет — для отправки и обновления заказов (POST). Не путайте их
местами.

Ключи присылаются отдельным сообщением, не вместе с этим документом. Храните
их в переменных окружения, не в коде и не в репозитории.

Если ключ отправлен не в тот эндпоинт, ответ прямо об этом скажет, а не вернёт
безликий 401:

```json
{"code":"mk_unauthorized","detail":"this endpoint expects the token; a secret key was supplied"}
```

---

## Шаг 1. Проверка доступа

Первым делом убедитесь, что ключ рабочий. Запросите список аптек — если
вернулся JSON, а не ошибка, всё настроено верно.

```bash
curl "https://api.fairhaven.uz/medicalka/v1/pharmacies?token=<ТОКЕН>"
```

Ожидаемый ответ:

```json
{ "items": [ { "id": 1, "name": "FAIRHAVEN HEALTH", "created_at": "2026-08-01T09:14:02" } ], "total": 1 }
```

Если вместо этого пришло `{"code":"mk_unauthorized",...}` — токен неверный или
отозван. Если `{"code":"mk_forbidden",...}` — токен отключён на нашей стороне,
свяжитесь с нами.

На Python:

```python
from fairhaven_client import FairHavenClient

client = FairHavenClient(token="<ТОКЕН>", secret="<СЕКРЕТ>")

pharmacy = client.list_pharmacies()["items"][0]

print(pharmacy["id"], pharmacy["name"])   # 1 FAIRHAVEN HEALTH
```

Филиал один, поэтому `pharmacy_id` при оформлении заказа передавать не нужно.

---

## Шаг 2. Чтение каталога

Каталог отдаётся постранично. Параметр `limit` — сколько товаров за раз
(максимум 1000), `skip` — сколько пропустить с начала.

```python
page = client.list_products(skip=0, limit=50)

for p in page["items"]:

    print(p["id"], p["name"], p["price"])
```

Карточка одного товара по `id`:

```python
product = client.get_product(1042)
```

```json
{

  "id": 1042,

  "name": "Fairhaven FertilAid Multivitamin for Women, №90",

  "manufacturer": "Fairhaven Health",

  "barcode": "4808000000000",

  "price": "500000.00",

  "updated_at": "2026-08-01T19:45:54"

}
```

**Важно про типы полей:** `id` и `total` — целые числа, а `price` и `quantity`
приходят строками (`"500000.00"`), не числами. Если нужно считать — приводите
сами. Для денег берите `Decimal`, а не `float`:

```python
from decimal import Decimal

total = Decimal(product["price"]) * 3
```

Весь каталог одним проходом, без ручной пагинации:

```python
for product in client.iter_products():

    save(product)
```

Рекомендуемая частота обновления каталога — **раз в час**.

---

## Шаг 3. Поиск товаров

Поиск идёт по названию, бренду, артикулу и штрихкоду одновременно.

```python
result = client.search_products("FertilAid", limit=20)

print(result["total"])          # сколько всего совпадений

for p in result["items"]:

    print(p["id"], p["name"])
```

---

## Шаг 4. Остатки

Эндпоинт остатков отдаёт только товары, которые реально есть в наличии.
Поэтому `is_available` там всегда `true` — отсутствующих в списке просто нет.

Все остатки постранично:

```python
inv = client.list_inventory(limit=100)

for row in inv["items"]:

    print(row["product_id"], "×", row["quantity"], "по", row["price"])
```

Точный остаток одного товара:

```python
stock = client.get_stock(product_id=1042)

if stock is None:

    print("Нет в наличии")     # API вернул 404 → метод отдаёт None

else:

    print(stock["quantity"], stock["price"])
```

Обратите внимание: если товара нет в наличии, прямой запрос остатка возвращает
**404**. В модуле это обёрнуто и превращается в `None`, чтобы не ловить
исключение на каждый отсутствующий товар.

Количество в ответе — это то, что **можно продать вам**: складской остаток
минус уже забронированное другими каналами, минус страховой запас аптеки.

Рекомендуемая частота обновления остатков — **раз в 5 минут**.

## Шаг 5. Оформление заказа

Заказы отправляются с секретом, а не токеном. Тело — данные покупателя и
список позиций. `pharmacy_id` указывать не нужно: филиал один.

```python
import uuid

order = {

    "order_id": str(uuid.uuid4()),                 # ваш уникальный id заказа

    "order_number": "MK-2026-005821",              # человекочитаемый номер

    "customer": {

        "first_name": "Иван",

        "last_name": "Иванов",

        "phone": "+998900000000",

    },

    "delivery_type": "delivery",

    "delivery_address": "г. Ташкент, ул. Махтумкули",

    "items": [

        { "product_id": 1042, "name": "FertilAid for Women", "quantity": 1 },

    ],

}

created = client.create_order(order)

print(created)   # {"wc_order_id": 1042, "status": "received"}
```

`product_id` — тот же `id`, что и в каталоге `/products`. В ответе `status`
будет `"received"` — заказ принят и записан.

**`wc_order_id` — целое число**, как и остальные `id` в API.

Три вещи, о которых стоит знать заранее:

**Повтор безопасен.** Отправка того же `order_id` вернёт тот же `wc_order_id` и
не создаст второй заказ. Если ответ не дошёл из-за таймаута — просто отправьте
ещё раз.

**Мы отвечаем сразу.** Резервирование товара на складе происходит уже после
ответа, поэтому медленный склад не задерживает подтверждение заказа.

**Цену считаем мы.** Поле `unit_price`, если вы его передадите, будет
прочитано и проигнорировано — берётся цена из нашего каталога. Так исключается
расхождение, когда у вас закешировалась старая цена.

## Шаг 6. Обновление статуса заказа

Когда статус меняется на вашей стороне (оплата, отмена) — сообщите нам.
Обращайтесь по тому `order_id`, который вы сами сгенерировали на шаге 5.

```python
client.update_order_status(order["order_id"], "paid")

# {"wc_order_id": 1042, "status": "processing"}
```

Допустимые статусы: `paid`, `payment_confirmed`, `cancelled`,
`cancelled_by_buyer`. Любое другое значение вернёт **422**, неизвестный
`order_id` — **404**.

Что происходит у нас:

| Ваш статус | Что происходит |
|---|---|
| `paid`, `payment_confirmed` | заказ проводится как продажа, остаток списывается |
| `cancelled`, `cancelled_by_buyer` | резерв снимается, товар возвращается в продажу |

Что возвращаем мы в поле `status`:

| Значение | Смысл |
|---|---|
| `received` | заказ принят и записан |
| `accepted` | остаток зарезервирован под ваш заказ |
| `processing` | проведён как продажа |
| `cancelled` | отменён, резерв снят |

Отмена уже проведённого заказа вернёт **422**: это возврат, он оформляется
отдельно и не через API.

## Обработка ошибок

API отвечает стандартными HTTP-кодами. В модуле-примере все они превращаются в
`FairHavenError` с полями `.status` и `.payload`.

| Код | Что значит | Что делать |
|---|---|---|
| 401 | Нет или неверный токен/секрет | Проверьте ключ и параметр (`token` / `secret`) |
| 403 | Ключ отключён на стороне аптеки | Свяжитесь с нами |
| 404 | Объект не найден | Проверьте id / товара нет в наличии |
| 422 | Неверные параметры запроса | Проверьте тело и обязательные поля |
| 429 | Слишком часто | Повторите позже — модуль делает это сам |

```python
from fairhaven_client import FairHavenError

try:

    client.get_product(999999999)

except FairHavenError as e:

    print(e.status, e.payload)   # 404 {"detail": "Product 999999999 not found"}
```

**Ограничение частоты:** 240 запросов в минуту на ключ. Рекомендованные выше
частоты опроса укладываются в него с большим запасом. При 429 модуль ждёт и
повторяет запрос автоматически, до трёх раз.

## Типовой сценарий целиком

1. При старте — `list_pharmacies()` для проверки доступа.
2. Раз в час — синхронизация каталога через `iter_products()`.
3. Раз в 5 минут — обновление остатков через `list_inventory()`.
4. Перед показом товара покупателю — `get_stock()`, чтобы не продать то, чего нет.
5. Покупатель оформил заказ — `create_order()`.
6. Прошла оплата — `update_order_status(order_id, "paid")`.
7. Покупатель отменил — `update_order_status(order_id, "cancelled_by_buyer")`.
