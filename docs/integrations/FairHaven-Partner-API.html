Руководство для разработчиков партнёра: как подключиться к API аптеки FairHaven Health, получать каталог и остатки, отправлять заказы и узнавать решение аптеки.

Это обычный HTTPS + JSON. Примеры — на curl, Python и Node.js, но подойдёт любой язык. Готовый модуль на Python со всеми методами — partner_client.py. Машиночитаемый контракт (OpenAPI 3) — partner-api.openapi.yaml, он же доступен по адресу https://api.fairhaven.uz/partner/openapi.yaml (импортируется в Postman, Insomnia или Swagger Editor).

Как устроена работа в двух словах: вы показываете своим покупателям наш каталог с нашими остатками, отправляете нам заказ, аптека принимает или отклоняет его в течение нескольких минут, принятый заказ резервируется, вы доставляете его покупателю и сообщаете нам, что заказ доставлен и оплачен — в этот момент продажа проводится в нашем учёте.

ЧтоЗначение

Ключи присылаются отдельным сообщением, не вместе с этим документом. Храните их в переменных окружения или в хранилище секретов — не в коде, не в репозитории и не в логах. Если ключ мог утечь, напишите нам: мы выпустим новую пару, старая перестанет работать сразу.

Как передавать ключ

В заголовке Authorization:

Authorization: Bearer fhp_t_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

или, если вашему HTTP-клиенту так удобнее, в заголовке X-Api-Key:

X-Api-Key: fhp_t_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

Ключ в адресе (?token=) не принимается.

Два ключа — две задачи

КлючЧто можно
Токен чтения fhp_t_…/me, каталог, остатки, просмотр заказов
Секрет заказов fhp_s_…всё то же плюс создание, отмена и завершение заказов, /webhook/test

Токен чтения можно спокойно отдать сервису, который только синхронизирует витрину. Секрет заказов нужен только той части вашей системы, которая оформляет заказы. Если на метод заказов отправить токен чтения, ответ будет 401 unauthorized с понятным текстом: this endpoint needs the order secret (fhp_s_…); the read token was sent.

3. Режимы подключения

РежимЧто происходит
testРаботает весь API. Каталог и остатки — настоящие. Заказы проходят все статусы, но не трогают реальный склад и учёт, аптека их не видит. Решение по заказу принимает робот примерно через 10–15 секунд.
liveБоевой режим: заказы получает оператор аптеки, товар резервируется, после complete проводится продажа.
offДоступ выключен: любой запрос отвечает 403 partner_disabled.

Каждый партнёр начинает в режиме test. Когда вы прошли тестовые сценарии (раздел 12), мы вместе проверяем интеграцию и переключаем вас в live. Ключи при этом не меняются. Текущий режим всегда виден в GET /me → partner.mode, а у каждого заказа есть поле test: true/false.

4. Быстрый старт (5 минут)

Положите ключи в переменные окружения:

bash
export FAIRHAVEN_TOKEN='fhp_t_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
export FAIRHAVEN_SECRET='fhp_s_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'
export FH='https://api.fairhaven.uz/partner/v1'

Шаг 1. Проверьте ключ.

bash
curl -s "$FH/me" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"
json
{
  "partner": { "code": "demo_partner", "name": "Demo Partner", "mode": "test" },
  "key": "token",
  "shop": { "name": "FAIRHAVEN HEALTH" },
  "webhook_configured": false,
  "server_time": "2026-11-12T08:00:00.000Z"
}

Шаг 2. Возьмите остатки.

bash
curl -s "$FH/stock?limit=500" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"
json
{
  "items": [
    { "product_id": 701, "quantity": 12, "available": true, "price": 145000 },
    { "product_id": 702, "quantity": 0, "available": false, "price": 89000 }
  ],
  "total": 2, "limit": 500, "offset": 0,
  "generated_at": "2026-11-12T08:00:01.000Z"
}

Шаг 3. Отправьте тестовый заказ.

bash
curl -s -X POST "$FH/orders" \
  -H "Authorization: Bearer $FAIRHAVEN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
        "order_id": "TEST-0001",
        "items": [ { "product_id": 701, "quantity": 2 } ],
        "customer": { "name": "Тестовый покупатель", "phone": "+998900000000" },
        "delivery": { "type": "courier", "address": "Ташкент, тестовый адрес, 1" }
      }'

Ответ 201 — заказ в статусе new, в поле decision_deadline — до какого времени аптека ответит.

Шаг 4. Узнайте решение (через 10–15 секунд в тестовом режиме):

bash
curl -s "$FH/orders/TEST-0001" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"

Статус accepted — товар зарезервирован, можно доставлять.

Шаг 5. Подтвердите доставку и оплату.

bash
curl -s -X POST "$FH/orders/TEST-0001/complete" \
  -H "Authorization: Bearer $FAIRHAVEN_SECRET"

Статус completed — цикл пройден.

5. Общие правила

  • Формат. Запросы и ответы — JSON в UTF-8. Для POST с телом указывайте Content-Type: application/json. Тело больше 256 КБ отклоняется (413 payload_too_large).
  • Деньги — целое число сумов (UZS), без тийинов и без дробной части: 145000 значит 145 000 сум.
  • Количество — целые штуки (unit: "pcs").
  • Время — ISO 8601 в UTC, например 2026-11-12T08:00:00.000Z. Ташкент — UTC+5.
  • Постраничный вывод — у /products, /stock, /orders: параметры limit (1–500, по умолчанию 100) и offset (с 0). Ответ: {"items": [...], "total": N, "limit": L, "offset": O}. Чтобы забрать всё, увеличивайте offset на limit, пока offset < total.
  • Ошибки всегда в одном виде (исключение — 429, см. раздел 8):
json
{
  "error": {
    "code": "insufficient_stock",
    "message": "not enough stock for some items",
    "details": { "items": [ { "product_id": 701, "requested": 5, "available": 3 } ] }
  }
}

Решения в вашем коде принимайте по error.code (он стабилен), message — пояснение для человека, details есть не всегда.

6. Каталог

GET /products — список товаров

Параметры: limit, offset, search (поиск по названию, бренду, артикулу или штрихкоду, до 100 символов, без учёта регистра). Сортировка — по названию.

curl -s "$FH/products?search=4600000000000" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"

GET /products/{id} — один товар

bash

Если товара больше нет в каталоге — 404 product_not_found.

Как часто обновлять каталог. Карточки меняются редко: достаточно полной выгрузки раз в час или раз в сутки. Цены и количество берите из /stock.

7. Остатки

GET /stock — остатки и цены всех товаров каталога

bash
curl -s "$FH/stock?limit=500&offset=0" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"
json
{
  "items": [
    { "product_id": 701, "quantity": 12, "available": true,  "price": 145000 },
    { "product_id": 702, "quantity": 0,  "available": false, "price": 89000 }
  ],
  "total": 2, "limit": 500, "offset": 0,
  "generated_at": "2026-11-12T08:00:01.000Z"
}

Важно:

  • В ответе все товары каталога, в том числе закончившиеся — с quantity: 0 и available: false. Товар, который пропал из списка, убран из каталога: снимите его с вашей витрины.
  • quantity — сколько можно продать именно вам: остаток в аптеке минус заказы других каналов продаж минус страховой запас для торгового зала. Заказывать больше этого числа нельзя.
  • price может меняться — всегда показывайте покупателю цену из последнего ответа.
  • Рекомендуемая частота опроса — раз в 1–5 минут (одна страница на 500 товаров обычно покрывает весь каталог).
  • Остаток меняется между запросами. Окончательную проверку делает POST /orders: если товара уже не хватает, вы получите 409 insufficient_stock с точными числами (раздел 9).

При превышении лимита запросов ответ — 429 с телом {"detail": "Too many requests — slow down and retry"} (не в общем формате ошибок) и заголовком Retry-After — через сколько секунд можно продолжать. Текущий расход виден в заголовках RateLimit и RateLimit-Policy каждого ответа. При опросе по рекомендациям этого документа лимит не достигается.

9. Заказы

9.1 Создание: POST /orders (секрет заказов)

bash
curl -s -X POST "$FH/orders" \
  -H "Authorization: Bearer $FAIRHAVEN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
        "order_id": "A-100045",
        "items": [
          { "product_id": 701, "quantity": 2 },
          { "product_id": 705, "quantity": 1 }
        ],
        "customer": { "name": "Тестовый покупатель", "phone": "+998900000000" },
        "delivery": { "type": "courier", "address": "Ташкент, тестовый адрес, 1", "comment": "Домофон 00" },
        "comment": "Позвонить за 15 минут"
      }'
ПолеОбязательноЧто это
order_idдаВаш уникальный номер заказа: до 64 печатных ASCII-символов без пробелов. По нему вы потом получаете, отменяете и завершаете заказ.
items[]да1–50 строк {product_id, quantity}; quantity — 1–999. Две строки с одним товаром складываются в одну.
customer.nameнетИмя покупателя, до 100 символов.
customer.phoneнетТелефон, до 32 символов.
delivery.typeнетcourier (по умолчанию) или pickup (самовывоз из аптеки).
delivery.addressнетАдрес, до 300 символов.
delivery.commentнетКомментарий к доставке, до 500 символов.
commentнетКомментарий к заказу, до 500 символов.
test_outcomeнетТолько в режиме test: "reject" — робот отклонит заказ. Любое другое значение или отсутствие — примет. В режиме live игнорируется.

Цены в запросе не передаются и не принимаются: заказ всегда считается по нашему каталогу. Цена и сумма каждой строки возвращаются в ответе — сверьте их со своими.

409 insufficient_stockНе хватает остатка; в details.items — что, сколько просили и сколько есть.

9.2 Жизненный цикл заказа

                    POST /orders
                         │
                         ▼
                   ┌───────────┐  аптека отклонила или
                   │    new    │─ не ответила вовремя ───────▶ rejected
                   └───────────┘  (rejected_by_shop / timeout)
                     │       │
       аптека приняла│       │ POST /cancel (вы)
      (товар в резерве)      └──────────────────────────────▶ cancelled
                     ▼                                          ▲
                   ┌───────────┐  POST /cancel (вы)             │
                   │ accepted  │─ или отмена аптекой ───────────┘
                   └───────────┘  (ваш текст / cancelled_by_partner /
                         │         cancelled_by_shop)
     POST /complete (вы):│
   доставлен и оплачен   ▼
                   ┌───────────┐
                   │ completed │  продажа проведена в учёте аптеки
                   └───────────┘
СтатусЧто значитЧто с товаром (режим live)Ваши действия
newЗаказ получен, аптека решает.Сразу снят с продажи в других каналах.Ждать решения; можно отменить.
acceptedАптека приняла.Зарезервирован в учёте аптеки.Доставить; затем complete или cancel.
rejectedАптека отклонила или не ответила вовремя.Возвращён в продажу.Сообщить покупателю. Финальный статус.
cancelledОтменён вами или аптекой.Возвращён в продажу.Финальный статус.
completedВы подтвердили доставку и оплату.Продан.Финальный статус.

Значения reason:

reasonСтатусКогда
rejected_by_shoprejectedОператор аптеки отклонил заказ (в тесте — робот по test_outcome: "reject").
timeoutrejectedАптека не ответила до decision_deadline (только live).
cancelled_by_partnercancelledВы отменили заказ без указания причины.
ваш текстcancelledВы отменили заказ и передали reason.
cancelled_by_shopcancelledАптека отменила заказ со своей стороны.

Окно решения. Аптека отвечает на заказ в течение окна решения — по умолчанию 5 минут (точное время каждого заказа — в decision_deadline). Если оператор не успел, заказ автоматически становится rejected с причиной timeout, а товар возвращается в продажу. В тестовом режиме решение принимает робот через ~10–15 секунд.

Каждая смена статуса — в том числе вызванная вашим же cancel или complete — приходит и webhook-событием. Это нормально: обрабатывайте событие идемпотентно (раздел 10).

9.4 Получение заказа: GET /orders/{order_id}

bash
curl -s "$FH/orders/A-100045" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"

По вашему order_id. Подходит любой ключ. Нет такого заказа — 404 order_not_found.

9.5 Список заказов: GET /orders

bash
curl -s "$FH/orders?status=accepted&limit=100&offset=0" -H "Authorization: Bearer $FAIRHAVEN_TOKEN"

Новые сверху. Фильтр status — один из new, accepted, rejected, cancelled, completed (другое значение — 422 validation_error). Удобно для сверки в конце дня и для восстановления после сбоя на вашей стороне.

9.6 Отмена: POST /orders/{order_id}/cancel (секрет заказов)

bash
curl -s -X POST "$FH/orders/A-100045/cancel" \
  -H "Authorization: Bearer $FAIRHAVEN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"reason": "Покупатель отказался"}'

Можно из статусов new и accepted. Тело необязательно; reason — до 200 символов, попадёт в поле reason заказа (без него — cancelled_by_partner). Резерв снимается, товар возвращается в продажу. Из других статусов — 409 invalid_status (в details.status — текущий статус).

9.7 Завершение: POST /orders/{order_id}/complete (секрет заказов)

bash
curl -s -X POST "$FH/orders/A-100045/complete" -H "Authorization: Bearer $FAIRHAVEN_SECRET"

Вызывайте, когда заказ доставлен и оплачен покупателем. Только из статуса accepted. В этот момент продажа проводится в учёте аптеки, поэтому:

  • не вызывайте complete заранее «на всякий случай» — отменить проведённую продажу через API нельзя;
  • если покупатель отказался — вызывайте cancel, а не complete;
  • повторный complete ничего не меняет и отвечает 409 invalid_status с details.status: "completed" — считайте это успехом;
  • при 503 billz_unavailable повторите через минуту;
  • при 503 sale_pending_review не повторяйте: продажу проверяет аптека, статус сменится сам — следите за webhook или опрашивайте заказ.

11. Webhooks — уведомления о смене статуса

Чтобы не опрашивать заказы, сообщите нам адрес https://… (только HTTPS, без логина и пароля в адресе, до 500 символов). Мы пришлём секрет подписи whsec_… — им вы проверяете, что запрос пришёл от нас.

11.1 Что приходит

POST на ваш адрес, Content-Type: application/json, User-Agent: FairHaven-Webhooks/1.0:

X-FairHaven-Event: order.status_changed
X-FairHaven-Event-Id: 6733a1f0c2e4b5a6d7e8f901
X-FairHaven-Timestamp: 1762934400
X-FairHaven-Signature: v1=5d41402abc4b2a76b9719d911017c592…
json
{
  "id": "6733a1f0c2e4b5a6d7e8f901",
  "type": "order.status_changed",
  "created_at": "2026-11-12T08:02:10.000Z",
  "data": { "id": 1042, "order_id": "A-100045", "status": "accepted", "…": "заказ целиком, как в GET /orders/{order_id}" }
}
Поле / заголовокЧто это
id, X-FairHaven-Event-IdУникальный id события. Повторная доставка приходит с тем же id.
type, X-FairHaven-Eventorder.status_changed или ping (проверка).
created_atВремя, когда произошло событие. Одинаково во всех повторных доставках.
dataДля order.status_changed — заказ целиком в состоянии на момент события. Для ping — {"message": "FairHaven webhook test"}.
X-FairHaven-TimestampВремя отправки, Unix-секунды.
X-FairHaven-Signaturev1= + hex HMAC-SHA256.

События приходят по каждой смене статуса: accepted, rejected, cancelled, completed. Создание заказа событием не сопровождается — его результат вы получаете в ответе на POST /orders. Тестовые заказы тоже присылают события (с data.test: true).

11.2 Как отвечать

  • Ответьте любым кодом 2xx быстро (до 10 секунд), тело ответа не читается. Тяжёлую обработку делайте после ответа, в очереди.
  • Любой другой код, перенаправление (3xx не выполняется), таймаут 10 секунд или сетевая ошибка — неудача. Повторы: через 10 с, 1 мин, 5 мин, 15 мин, 1 ч, 3 ч, 6 ч, 12 ч; после этого событие больше не отправляется (заказ по-прежнему доступен через GET /orders/{order_id}).
  • Доставка «как минимум один раз»: одно событие может прийти дважды. Запоминайте обработанные id и пропускайте повторы.
  • Порядок сохраняется: пока более старое событие не доставлено, более новые ваших заказов ждут его. Новый статус не обгонит старый.
  • События, возникшие, пока адрес webhook не был задан, позже не досылаются — сверьтесь через GET /orders.

11.3 Проверка подписи

Подпись считается от сырого тела запроса (байты как пришли, до разбора JSON):

signature = hex( HMAC-SHA256( webhook_secret, "<X-FairHaven-Timestamp>.<сырое тело>" ) )
X-FairHaven-Signature: v1=<signature>

Проверьте подпись сравнением за постоянное время и отклоняйте запросы со временем старше ~5 минут (защита от повтора перехваченного запроса). Каждая повторная попытка подписывается заново, со свежим временем.

Python (Flask):

python
import hashlib, hmac, os, time
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = os.environ["FAIRHAVEN_WEBHOOK_SECRET"]  # whsec_…
seen_ids = set()  # в продакшене — таблица в БД с уникальным ключом


def verify(secret: str, timestamp: str, raw_body: bytes, signature: str, max_age: int = 300) -> bool:
    try:
        ts = int(timestamp)
    except (TypeError, ValueError):
        return False
    if abs(time.time() - ts) > max_age:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(f"v1={expected}", signature or "")


@app.post("/fairhaven/webhook")
def fairhaven_webhook():
    raw = request.get_data()  # сырые байты, до разбора JSON
    if not verify(WEBHOOK_SECRET,
                  request.headers.get("X-FairHaven-Timestamp", ""),
                  raw,
                  request.headers.get("X-FairHaven-Signature", "")):
        abort(401)
    event = request.get_json()
    if event["id"] in seen_ids:
        return "", 204  # повтор — уже обработали
    seen_ids.add(event["id"])
    if event["type"] == "order.status_changed":
        order = event["data"]
        # поставьте в очередь: обновить заказ order["order_id"] → order["status"]
    return "", 204

Node.js (Express):

js
const crypto = require('crypto');
const express = require('express');

const app = express();
const WEBHOOK_SECRET = process.env.FAIRHAVEN_WEBHOOK_SECRET; // whsec_…
const seenIds = new Set(); // в продакшене — таблица в БД с уникальным ключом

function verify(secret, timestamp, rawBody, signature, maxAge = 300) {
  const ts = Number(timestamp);
  if (!Number.isInteger(ts) || Math.abs(Date.now() / 1000 - ts) > maxAge) return false;
  const expected = 'v1=' + crypto.createHmac('sha256', secret)
    .update(`${timestamp}.`).update(rawBody).digest('hex');
  const a = Buffer.from(expected);
  const b = Buffer.from(String(signature || ''));
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

// express.raw — чтобы получить тело байтами, а не уже разобранный JSON
app.post('/fairhaven/webhook', express.raw({ type: 'application/json' }), (req, res) => {
  if (!verify(WEBHOOK_SECRET, req.get('X-FairHaven-Timestamp'), req.body, req.get('X-FairHaven-Signature'))) {
    return res.sendStatus(401);
  }
  const event = JSON.parse(req.body.toString('utf8'));
  if (seenIds.has(event.id)) return res.sendStatus(204);
  seenIds.add(event.id);
  if (event.type === 'order.status_changed') {
    const order = event.data;
    // поставьте в очередь: обновить заказ order.order_id → order.status
  }
  return res.sendStatus(204);
});

app.listen(3000);

Частая ошибка — считать подпись от заново сериализованного JSON (JSON.stringify(req.body), json.dumps(...)): порядок ключей и пробелы могут отличаться, подпись не сойдётся. Берите сырое тело.

11.4 Проверка адреса: POST /webhook/test (секрет заказов)

bash
curl -s -X POST "$FH/webhook/test" -H "Authorization: Bearer $FAIRHAVEN_SECRET"

Мы сразу отправим на ваш адрес событие ping (подписанное так же, как настоящие) и вернём результат:

12. Без webhook: опрос

Webhook не обязателен. Без него:

  1. После POST /orders опрашивайте GET /orders/{order_id} раз в 10–30 секунд, пока статус new. Решение придёт не позже decision_deadline (плюс несколько секунд).
  2. Заказы в accepted можно проверять реже — раз в несколько минут: аптека может отменить заказ (cancelled_by_shop) или завершённая продажа может выйти из проверки (sale_pending_review).
  3. Для сверки — GET /orders?status=new и GET /orders?status=accepted.

Даже с webhook полезно раз в 10–15 минут сверять открытые заказы опросом — на случай, если ваш сервер был недоступен дольше суток.

13. Тестовый режим: что проверить

14. Переход в боевой режим

Перед переключением в live:

  • Все сценарии раздела 13 пройдены.
  • Ключи лежат в переменных окружения / хранилище секретов, не в коде и не в логах; секрет заказов есть только у сервиса оформления заказов.
  • Витрина берёт цены и количество из /stock и обновляет их не реже раза в 5 минут; товары, пропавшие из /stock, снимаются с продажи.
  • order_id боевых заказов уникальны и не пересекаются с тестовыми.
  • Покупатель видит отказ, если заказ rejected (в том числе по timeout).
  • complete вызывается только после доставки и оплаты; отказ покупателя ведёт к cancel.
  • Webhook проверяет подпись и время, отвечает быстро, пропускает повторы — или настроен опрос по разделу 12.
  • Есть контакт ответственного с вашей стороны на случай проблем.

Затем согласуем с вами время, вместе проведём первый реальный заказ и переключим режим. Ключи не меняются — меняется только partner.mode в GET /me.

15. Частые вопросы

**Товар закончился между запросом /stock и заказом. Что будет?** Заказ не создастся: ответ 409 insufficient_stock, в details.items — по каждому товару requested (сколько просили) и available (сколько есть сейчас). Ни одна строка заказа не резервируется. Предложите покупателю доступное количество и отправьте заказ заново.

Можно ли повторно отправить заказ, если ответ не дошёл? Да, это безопасно: отправьте его с тем же order_id. Если заказ уже создан, придёт 200 с сохранённым заказом, второго не будет. Учтите: при повторе возвращается первоначальный заказ, новое тело запроса не применяется. Чтобы оформить другой состав, используйте новый order_id. Если первая попытка закончилась ошибкой (409, 422, 404), заказ не создан, и тот же order_id можно использовать снова.

Как узнать решение аптеки? Webhook order.status_changed (раздел 11) или опрос GET /orders/{order_id} (раздел 12). Решение придёт не позже decision_deadline: accepted — принят, rejected — отклонён (reason покажет, отклонил оператор или истекло время).

Можно ли изменить заказ (состав, адрес)? Нет. Отмените заказ (cancel) и отправьте новый с новым order_id.

Сколько держится резерв по принятому заказу? Пока вы не вызовете complete или cancel (или аптека не отменит заказ). Пожалуйста, закрывайте заказы сразу после доставки или отказа — пока резерв висит, товар недоступен другим покупателям.

Почему цена в заказе отличается от цены на моей витрине? Заказ всегда считается по текущей цене нашего каталога. Если цена изменилась после вашего последнего /stock, в ответе на POST /orders будет новая цена. Обновляйте /stock чаще или сверяйте total ответа со своим и при расхождении отменяйте заказ.

Самовывоз поддерживается? Да: "delivery": {"type": "pickup"}. Адрес можно не указывать.

**Что значит test: true у заказа в боевом режиме?** Это заказ, созданный ещё в тестовом режиме: режим фиксируется при создании заказа. Склад и учёт он не трогает.

**Пришёл 503 sale_pending_review на complete. Что делать?** Ничего не повторять. Учётная система ответила неоднозначно, и продажу проверяет сотрудник аптеки. Когда он закончит, статус заказа сменится сам и придёт webhook.

Нужно ли подтверждать webhook телом ответа? Нет, важен только код 2xx. Тело ответа не читается.
