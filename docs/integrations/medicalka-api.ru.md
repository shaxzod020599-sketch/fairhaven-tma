# Fairhaven Health — API для Medicalka

Документ для интеграционной команды Medicalka.
Версия 1 · 31.07.2026

---

## Базовый адрес

```
https://api.fairhaven.uz/medicalka/v1
```

Только HTTPS. Ответы — `application/json; charset=utf-8`.

## Ключи

Выдаются два ключа с разными правами:

| Ключ | Параметр | Права | Формат |
|---|---|---|---|
| Токен | `?token=` | чтение каталога и остатков (GET) | `fhm_t_…` |
| Секрет | `?secret=` | приём и обновление заказов (POST) | `fhm_s_…` |

Ключ — 51 символ, только `A–Z a–z 0–9 _ -`, экранирование в URL не требуется.

Префикс кодирует назначение: `t` — токен, `s` — секрет. Если ключ отправлен не
в тот эндпоинт, ответ прямо об этом сообщит, а не вернёт безликий 401:

```json
{"code":"mk_unauthorized","detail":"this endpoint expects the token; a secret key was supplied"}
```

Ключи хранятся у нас только в виде SHA-256, восстановить их нельзя — при утрате
выпускается новый. Ротация безопасна: новый ключ начинает работать сразу, старый
продолжает действовать, пока вы не подтвердите переход.

Держите ключи в переменных окружения, не в коде и не в репозитории.

## Шаг 1. Проверка доступа

```bash
curl "https://api.fairhaven.uz/medicalka/v1/pharmacies?token=<ТОКЕН>"
```

```json
{
  "items": [
    { "id": 1, "name": "FAIRHAVEN HEALTH", "created_at": "2026-07-31T09:14:02" }
  ],
  "total": 1
}
```

Филиал один, поэтому `pharmacy_id` при оформлении заказа передавать не нужно.

---

## Типы полей

Совпадают с вашим руководством, повторяем во избежание разночтений:

| Поле | Тип |
|---|---|
| `id`, `product_id`, `pharmacy_id`, `total` | целое число |
| `price`, `quantity` | **строка** с двумя знаками после запятой — `"749000.00"` |
| `updated_at`, `created_at` | строка `YYYY-MM-DDTHH:MM:SS` (UTC, без смещения) |

Для арифметики приводите `price` и `quantity` к числу самостоятельно.

## Шаг 2. Каталог

```
GET /products?skip=0&limit=50
```

`limit` — максимум 1000, по умолчанию 50. `skip` — смещение от начала.

```json
{
  "items": [
    {
      "id": 25432,
      "name": "Fairhaven OvaBoost, №120",
      "manufacturer": "FAIRHAVEN HEALTH",
      "barcode": "895749000851",
      "price": "600000.00",
      "updated_at": "2026-07-24T11:34:43"
    }
  ],
  "total": 42
}
```

Карточка одного товара:

```
GET /products/{id}
```

`total` — общее число доступных вам позиций, а не размер страницы.

> В каталог попадают только товары, для которых у нас задана цена для Medicalka
> и включена выдача. Товар без назначенной цены не публикуется — так исключается
> продажа по нулевой цене.

---

## Шаг 3. Поиск

```
GET /products/search?q=Life E&limit=20
```

Ищет по названию, производителю, артикулу и штрихкоду одновременно.
Пустой `q` → `422`.

---

## Шаг 4. Остатки

```
GET /inventory?skip=0&limit=100
```

Возвращает только позиции, реально имеющиеся в наличии, поэтому
`is_available` всегда `true`: отсутствующих товаров в списке просто нет.

```json
{
  "items": [
    {
      "pharmacy_id": 1,
      "product_id": 25432,
      "quantity": "20.00",
      "price": "600000.00",
      "is_available": true
    }
  ],
  "total": 18
}
```

Остаток одной позиции:

```
GET /stock?pharmacy_id=1&product_id=25432
```

Если товара нет в наличии — **404**. Это ожидаемый ответ, а не ошибка: ваш
клиент превращает его в `None`.

`quantity` — свободный остаток: складской минус уже зарезервированный под
принятые заказы. То есть это количество, которое действительно можно продать.

Остатки обновляются из учётной системы каждые 5 минут.

## Шаг 5. Заказы

```
POST /orders?secret=<СЕКРЕТ>
POST /orders/{order_id}/status?secret=<СЕКРЕТ>
```

> **Пока не включено.** Оба эндпоинта отвечают `501` с пояснением. Мы сообщим
> отдельно, когда приём заказов будет открыт — контракт не изменится, вы сможете
> начать с чтения каталога уже сейчас.

Планируемое поведение: тело заказа и допустимые статусы — как в вашем
руководстве (`paid`, `payment_confirmed`, `cancelled`, `cancelled_by_buyer`;
любое другое значение → `422`, неизвестный `order_id` → `404`).

---

## Коды ответов

| Код | Значение | Что делать |
|---|---|---|
| 200 | успех | — |
| 401 | `{"code":"mk_unauthorized","detail":"…"}` — ключ неверный, неизвестный или отправлен не в тот эндпоинт | проверьте ключ и параметр (`token` / `secret`) |
| 403 | `{"code":"mk_forbidden","detail":"…"}` — ключ отключён на нашей стороне | свяжитесь с нами |
| 404 | `{"detail":"…"}` — объект не найден либо товара нет в наличии | ожидаемо для `/stock` |
| 422 | `{"detail":"…"}` — некорректные параметры запроса | см. текст `detail` |
| 429 | превышена частота запросов | повторите позже, см. ниже |
| 5xx | ошибка на нашей стороне | повторите с экспоненциальной паузой |

Поле `detail` всегда содержит человекочитаемую причину — используйте его при
разборе проблем.

---

## Частота запросов

Ограничения мягкие и рассчитаны на нормальную синхронизацию. Рекомендуемый режим:

| Задача | Частота |
|---|---|
| Каталог `/products` | раз в час |
| Остатки `/inventory` | раз в 5 минут |
| `/stock` перед показом товара покупателю | по необходимости |

Постраничный обход каталога делайте последовательно, а не параллельно.
При `429` подождите и повторите — счётчик сбрасывается за минуты.

---

## Типовой сценарий

1. При старте — `/pharmacies` для проверки ключа.
2. Раз в час — обход `/products` постранично.
3. Раз в 5 минут — `/inventory`.
4. Перед показом товара — `/stock`, чтобы не продать отсутствующее.
5. Заказы — после того, как мы откроем эндпоинты.
