# Fairhaven Health → Medicalka — краткая памятка

Одна страница для быстрого старта. Полное описание всех полей и ошибок —
в основном документе `medicalka-api.ru.md`.

## Доступ

```
Базовый адрес:  https://api.fairhaven.uz/medicalka/v1
```

Мы передаём вам два ключа (по защищённому каналу, отдельно от этого документа):

| Ключ | Как передаётся | Что можно |
|---|---|---|
| **token** (`fhm_t_…`) | `?token=` в каждом GET | читать каталог и остатки |
| **secret** (`fhm_s_…`) | `?secret=` в каждом POST | отправлять заказы и статусы |

Ключи не взаимозаменяемы. Храните в переменных окружения, не в коде.

## Эндпоинты

```
GET  /pharmacies                       проверка доступа, список филиалов (один)
GET  /products?skip=&limit=            каталог
GET  /products/search?q=               поиск
GET  /products/{id}                    карточка
GET  /inventory?skip=&limit=           остатки (только то, что в наличии)
GET  /stock?product_id=                остаток одного товара; нет в наличии → 404
POST /orders                           новый заказ
POST /orders/{order_id}/status         смена статуса (`wc_order_id` тоже принят)
```

## Типы данных — важно

`id`, `product_id`, `pharmacy_id`, `total`, `quantity` — **целые числа**.
`base_price` и `price` — **числа**. Это формат импортера Medicalka v2.

## Фискальные коды

В карточке товара приходят два кода — строками из цифр:

| Поле | Что это |
|---|---|
| `ikpu` | ИКПУ (MXIK) — код товара в справочнике налоговой |
| `package_code` | код упаковки — единица, в которой товар продаётся |

Задаются на нашей стороне и могут меняться. Берите из ответа при каждой
синхронизации, не храните как константу.

## Фотографии

`images` — список: `[{ "url": "https://…", "hash": "<sha1 байтов>" }]`.
Первая картинка основная. Пустой список — фотографии нет.

`hash` не изменился → файл тот же, можно не скачивать заново.

Ключ для картинок **не нужен**: файлы публичные. Не добавляйте `?token=` к
адресу картинки.

## Текущий безопасный режим

При `BILLZ_WRITE_ENABLED=false` legacy `POST /orders` не оформляет продажу и
возвращает `503 mk_unavailable`. Основной поток заказов идёт через partner API:
сначала pharmacy approval, затем после оплаты — `paid` sub-order. Само
подтверждение заявки остаток в Billz не уменьшает.

## Заказ

```json
POST /orders?secret=…
{
  "order_id": "ваш номер заказа",
  "customer": { "first_name": "…", "phone": "+998…" },
  "delivery_address": "…",
  "items": [ { "product_id": 1, "quantity": 2 } ]
}
→ { "wc_order_id": 1042, "status": "received" }
```

- `wc_order_id` — **целое число**, как и все `id` в API.
- Повтор того же `order_id` вернёт **тот же** `wc_order_id` — дубликатов не будет.
- Цена берётся из нашего каталога; `unit_price` в запросе игнорируется.

## Статусы

Обращайтесь **по своему `order_id`** — тому, что вы сгенерировали при создании.
Наш `wc_order_id` тоже принимается.

```json
POST /orders/{order_id}/status?secret=…   { "status": "paid" }
→ HTTP 503 — запись в Billz выключена
```

Для `payment_confirmed` ответ в безопасном режиме такой же.

### После отдельной активации боевого режима

Только после включения `BILLZ_WRITE_ENABLED=true` и перехода на боевые ключи:

```json
POST /orders/{order_id}/status?secret=…   { "status": "paid" }
→ { "wc_order_id": 1042, "status": "processing" }
```

| Статус | Действие у нас |
|---|---|
| `paid`, `payment_confirmed` | продажа проводится, остаток списывается |
| `cancelled`, `cancelled_by_buyer` | бронь снимается, товар возвращается в продажу |
| `received`, `accepted` | подтверждение, ничего не меняет |

Отмена уже оплаченного заказа → `422` (это возврат, оформляется отдельно).

## Ошибки

```json
401 { "code": "mk_unauthorized", "detail": "…" }   ключ неверный
403 { "code": "mk_forbidden",   "detail": "…" }    ключ отключён
404 { "detail": "…" }                              нет товара / нет в наличии
422 { "detail": "…" }                              неверные параметры
429 { "detail": "…" }                              слишком часто, повторите позже
```

## Частота опроса

Каталог — раз в час. Остатки — раз в 5 минут. Лимит: 240 запросов/мин на ключ.
